# 统一订阅迁移与回滚

生产切换结论为 **NO-GO**。§5.1 的限额等价性、历史分享和未用兑换承诺仍需核对。PR5 可随 0028 扩展发布，两个统一订阅开关保持默认关闭，生产权威仍为旧路径。

## 切换前

1. 固定 Worker commit、部署版本和 D1 迁移编号。备份 D1 以及相关 KV 数据和版本化配置，记录加密密钥版本及恢复权限。记录表行数、`foreign_key_check`、索引、触发器、旧订阅按格式输出摘要及测试基线。限制备份与输出访问，禁止在日志记录完整链接。
2. 在隔离状态应用 0028，做全量与增量验证。0028 增加检查点和旧订阅映射。每个用户是一个原子批次，模板按旧订阅单独创建，保留原开始、到期、暂停与撤销状态，保留旧记录及原兑换回执。
3. 管理端打开 **用户管理 → 订阅迁移**，选用户并点 **预检**。用 **导出预检** 保存脱敏结果。预检为只读。候选用户经过 **执行影子迁移 → 确认执行** 后写入影子数据，随后显示对账。中断后可重新预检或单独运行对账。用户令牌沿用已有统一令牌，首次生成独立随机令牌。
4. 按用户保留对账结果并汇总一致和暂缓数，处理孤立订阅、计划限额、旧分享、版本差异及未用兑换承诺。映射过期或对账失败须暂缓，并由管理员处理，保持旧权威。已签发兑换码仍保留原记录及快照，确认切换后实际核销行为可以兑现原承诺。
5. 取得切换批准后冻结旧写入口、旧批量任务和相关旧数据变更，处理最后的增量，重跑对账和所有客户端抽样。验证变更的专属模板、资源范围、令牌、授权边界与额度。冻结和权威切换由发布流程负责。
6. 在受控维护窗口提交权威切换，再开启新 API/UI 并按需重编译。记录与开关协调生效的 `unified_subscription_cutover_at`，其值为 UTC Unix 毫秒整数。兼容入口继续提供 90 天，校验旧凭据、账户、源版本、映射、旧授权与当前有效绑定，并限制在迁移时记录的节点范围内。过期或无安全映射的旧链接返回拒绝。历史分享有有效承诺且无法安全处理时推迟切换。
7. 审查观察期趋势和 90 天到期行为，按批次抽样重新核验。PR6 收缩前取得管理员批准，完成所有引用迁移，复验 D1 外键、触发器和备份恢复。

## PR6 收缩门槛与执行顺序

[待批准、未执行的 SQL 草案](unified-subscription-pr6-delete-PENDING-APPROVAL-NOT-EXECUTED.sql) 位于 `docs/`，当前发布仍处于 **NO-GO**。逐项审计、恢复数据和本地 D1 结果见 [PR6 准备报告](../REPORT_SUB_UNIFIED_PR6_PREP.md)。

1. 确认切换成功，生产观察期和 90 天旧链接兼容窗口均已结束。核对历史分享、未兑现兑换承诺及计划限额等价性，确认可退役的入口和授权范围。逐项关闭报告中的应用层依赖，验证管理端、公开链接、计划、兑换、转换、批任务和恢复流程。
2. 进入维护窗口，冻结旧写入，排空编译与批量任务。固定 Worker 与 schema 版本，取得新的 D1、KV 和配置恢复点，演练恢复和切换后权威写入的重放，核对行级数据、外键、视图、触发器和关键入口。确认归档的数据保留期限、访问权限以及账户、计划、节点和分组仍受历史关联约束的影响，取得 Roye 对此次收缩的明确批准。
3. 对照当前库的 `sqlite_schema` 和各表 `foreign_key_list`，核实父表的六条入向外键、各子表的入向引用及相关视图和触发器。任何漂移先复核。保持外键开启，在一个原子 D1 批次中复制父表到归档，暂移妨碍重建的视图和分组触发器，逐个重建六张子表并恢复索引，再恢复共享视图和保护触发器，最后删除旧业务父表。窗口内复验完整性、行数、映射、回执和外键，再开放写入。
4. 随正式收缩版本更新 schema bootstrap、迁移检测、备份脚本及 Worker fixtures，并验证从空库启动和存量库升级两条路径。当前全新库仍顺序应用 `migrations/` 至 0028。恢复 SQL 导出时按实际 schema 判断起点，空 `d1_migrations` 台账不能作为补跑历史迁移的依据。

## 指标与告警

以下为观察期建议阈值，由运行环境和基线决定最终数值。按路由类别、格式和状态码聚合，禁止添加链接、令牌、节点凭据或用户 ID 作为标签。

| 指标 | 初始告警 |
| --- | --- |
| Worker CPU | 每 5 分钟统计 p95，连续 3 个窗口超过环境 CPU 配额的 70% |
| D1 rows read | 每请求 p95 连续 3 个窗口超过测试基线的 2 倍，区分命中与重新编译 |
| 内部缓存命中率 | 预热后 15 分钟低于 70%，分开统计兼容渲染 |
| 429 和编译饱和 | 10 分钟 429 超过 5%，或编译忙占 1% 以上 |
| 编译错误 | 10 分钟失败率超过 1%，鉴权拒绝、格式错误与服务失败分开计数 |
| 请求放大率 | D1 操作数或读取行数连续 3 个窗口超过基线的 2 倍，订阅请求触发任何上游抓取立即告警 |

初始上限为 32 个绑定、2000 个节点、2 MB 输出（按 MiB 计）。保留现有 Catalog 上限。统一产物按用户及权威依赖标识缓存，必须经过鉴权才可读取，过期边界和编译完成后再次检查。相同编译任务在同一 Worker 实例去重，同实例最多并行四次统一编译，饱和返回明确错误。兼容入口独立限制并发且禁用缓存。编译和批量操作分别运行，模板更新通过版本依赖触发按需重编译。

## 回滚

切换前保持旧权威，可回退旧读路径并继续保留增量表。若已经切换，停止授权与兑换写入，进入维护模式，再向前修复或执行已验证的反向迁移。切换后旧表缺少新的绑定、兑换和人工变更，禁止直接部署旧 Worker。需要恢复时先在隔离环境恢复备份，重放切换后的权威写入，对账通过后再切流。保留审计及映射。

审查回滚点时记录 D1 与 KV 的同时点及写入重放边界。收缩批次失败时保持维护模式，核实事务回滚、旧 schema 和外键检查结果。收缩成功后需要回退时，先在隔离库恢复收缩前的 D1、KV 和配置，或应用经过验证的反向迁移重建旧表、外键、视图、触发器和索引。重放恢复点之后的绑定、兑换、令牌轮换及人工变更，按用户对账，复验回执和授权范围，再由发布流程切流。归档表用于保全历史行，回滚仍需处理恢复点之后的权威写入。

## 本地恢复演练

在 loop5 的隔离浏览器夹具完成一次影子迁移后，停止本地 Worker。归档 D1 和 KV 状态，展开到另一个持久化目录，使用 SQLite 检查源与恢复副本的完整性、外键、总量和映射关联，再用 Wrangler 指向恢复目录读取结果。压缩归档为 40 KB，恢复前后均有 27 条迁移记录、1 个用户、1 条旧订阅、1 条绑定、1 条映射、1 条检查点、1 个节点、6 条审计记录和 4 个 KV blob。无外键违规。切换前在真实部署环境重新演练，覆盖切换后需要重放的写入


PR6 准备阶段另用 259 KB 的 PR5 生产 SQL 导出在本地空 SQLite 恢复。导出对应 70 张表、694 行，完整性通过，外键违规 0。对隔离副本补 0028 后为 72 张表、694 行，既有表逐行一致。恢复演练覆盖该 SQL 导出的 D1 数据，KV、配置及切换后写入重放需在正式收缩前纳入完整演练
