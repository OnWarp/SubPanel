# 旧字段与兼容数据清理提案

审批状态为待审。执行前需由 Roye 单独批准范围和时间窗

| 候选 | 影响面 | 进入清理的前置条件 |
| --- | --- | --- |
| `subscriptions.device_limit` | 历史计划、账户详情、迁移与管理端 DTO。当前值存在但设备上限执行能力另需核对 | 新 API 舍弃或替代该展示能力后，核对历史非默认值及全部读写调用 |
| `subscriptions.plan_source`、`subscriptions.plan_note` | 历史计划来源、操作者备注、管理员发放、撤销与旧用户详情 | 对照 `subscription_creation` 和审核记录确认来源、备注各自的保留映射。无法映射的数据归档后再评审 |
| `system_settings` 中 `mail_smtp_pass`、`mail_resend_api_key` | 旧邮件配置、旧版本回滚和数据备份 | Workers secret 覆盖、邮件投递演练、上一安全版本也依赖 secrets。审批范围应包含供应商凭据轮换 |
| 历史 KV `state:delivery`、`state:accounts`、`state:catalog`、`system:crypto` | 旧导入工具、排障和密钥恢复，可能携带账本或凭据 | 先验证 D1 权威标记和离线对账，妥善保管对应密钥。稳定运行窗口后移除旧导入入口，再评审 KV 清理 |
| 历史同步 JSON 的 `etag` | 旧同步诊断记录及导出 | 先确认历史记录保留策略。对旧日志、KV、D1 备份分别界定审批范围 |

长期兼容字段包括 `subscriptions.token_hash`、`token_prefix`、`encrypted_token`、归属、期限、额度、分组、直选关系及 `last_reminded_at`。它们仍支持旧链接、有效性判断、续期提醒或数据恢复。规则模板表结构维持现行契约

1. **盘点**。从离线副本统计候选字段的空值率、默认值率和独有信息，核对脚本、SQL、导出、DTO、预览及上一版 Worker。记录版本、总数、外键及旧链接抽查
2. **扩展与兼容**。若需要替代存储，先添加并回填，采用新旧读取兼容，核对逐记录等价和恢复。备份和迁移台账按权限保存，密钥单独管理
3. **切换窗口**。发布兼容版，停止旧字段写入，采集读写证据，验证业务及旧客户端。对比回滚版本和当前版本对结构的要求
4. **审批后的收缩**。分步骤处理单项候选，每步留可恢复快照，先在隔离环境验证。如果需要表重建，复核索引、外键、约束、触发器、行数与关键字段，保留回切窗口。清理期间异常先停止后续批次
5. **回切**。收缩前使用上一兼容 Worker。收缩后的恢复需要离线还原候选结构和相关值，核对维护窗口期间新写入并有序合并，再切回兼容应用版本。整库恢复可能覆盖窗口内的新写入，需要独立审批

P4 交付只包含本提案和只读对账
