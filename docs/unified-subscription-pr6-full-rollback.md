# PR6 全量收缩恢复方案

## 恢复点

在维护窗口冻结授权、兑换、令牌轮换、分享及管理员业务写入。记录 D1、KV 和配置的同一恢复点以及 Worker 提交。保存 D1 导出、KV 备份、配置与密钥版本引用，复核校验和和恢复权限。核实两项就绪标志为 true、编译队列为空，并确认旧模板与其转换依赖没有新数据。该批次仍须经发布方执行。

## 批次失败

保持维护窗口。核实旧订阅、旧模板、转换表和六条旧外键仍在，确认未遗留归档或守卫表，运行完整性与外键检查。检查失败条件并重新比对 schema，再决定是否重试。守卫命中旧模板或转换数据时，先核对来源、用途与迁移路径。

## 批次成功后需要恢复

1. 停止新的业务写入并保存收缩后的 D1、KV 和配置，用审计记录与两份快照确定需要重放的写入区间。
2. 在新隔离库恢复收缩前 D1、KV、配置与匹配的加密密钥版本。以恢复点的 schema 和迁移台账为准，核对旧订阅、模板、发布版本、默认指针、转换依赖、六条外键、兑换联合视图、触发器和索引。保持统一订阅切换状态。
3. 按顺序重放恢复点之后的权威写入，覆盖授权绑定及修订、兑换消耗及回执、访问令牌、分享、账户和目录变更。用请求幂等键及审计目标去重。缺少可验证的写入记录时保持维护状态，先补齐数据差异。
4. 逐用户核对账户状态、绑定模板、授权起止、节点范围、有效访问令牌和兑换记录。核对完整性、外键、计划和目录，验证管理员写入及公开统一订阅。由发布方切换到恢复库与对应 Worker 后再开放写入。

本次演练验证了 D1 SQL 恢复和收缩。生产 KV、密钥版本恢复及切换后写入重放仍需在发布前独立验证。
